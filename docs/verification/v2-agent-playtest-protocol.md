# 独立 agent 模拟试玩协议

用户于2026-10-14要求“先设计几个agent来玩”。本轮使用5名没有继承开发对话或谜底的独立agent。它们是合成测试参与者，不是真人，不用于估计真实玩家成功率或认知速度。

| 参与者 | 案件 | 语言与测试侧重 |
| --- | --- | --- |
| P01 | 霓虹血迹 | 中文，先观察和阅读提示 |
| P02 | 幽灵协议 | 英文，关注键盘和资源成本 |
| P03 | 红蝶陷阱 | 中文，390×844手机布局、指针模拟操作 |
| P04 | 白塔悖论 | 中文，深入比较责任归因和证据 |
| P05 | 深潮回声 | 英文，探索并解释证据链 |

每人使用独立本地端口/内存SQLite运行，默认探员队伍、初始20 AP、调查内容版本2。测试调用真实Worker处理函数；只替换账号/传输连接，不连接生产用户、Firebase登录或生产D1，也没有真实付费或奖励。完整入口、教程、现场调查和报告UI保留。

参与者只能看可见浏览器DOM、截图，使用正常按钮/键盘、提示及3D/文字切换。禁止读取源码、测试答案、服务端内容、隐藏JavaScript状态、其他参与者报告；禁止直接调用接口、数据库修改或枚举选项撞答案。它们可以为自己的报告保存截图和JSON。

从首次进入调查场景计时，记录第一次取得有效线索、误操作、卡点、成本理解、提示使用、最终AP/评级以及机会/手段/动机/时间线的自述。若AP耗尽或一个卡点持续超过3分钟，保留失败状态与原因，不强行制造通过。浏览器工具调用及agent推理耗时均包含在观察时间中，不能与真人反应时间直接比较。

P01/P02/P04先并行运行，P03在其他宽屏测试结束后使用手机视口，避免浏览器全局尺寸影响并行参与者。P05补测另一种并列比对场景。测试页面在后台操作，参与者只关闭自己的临时页。

这是边玩边修的形成性检查。发现问题时主任务可修复并告知相应参与者界面/环境修复情况，但不会给案件答案或重置其付费进度；结果中保留修复前的失败经历。修复后的专项自动测试与实际UI复查单独记录，不能将其包装成一轮冻结版本的盲测。

结果见[agent模拟试玩记录](v2-agent-playtests.md)。真实5–8名新玩家研究与实际手机GPU/触屏测试仍是单独的后续步骤。
