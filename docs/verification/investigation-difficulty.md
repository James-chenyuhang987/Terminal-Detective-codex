# 调查难度调整 · balance revision 2

日期：2026-10-15（Asia/Singapore）。本轮依据[五名 agent 形成性试玩](v2-agent-playtests.md)调整资源与反馈。原试玩结果保留，下面的回归和界面 QA 不是新一轮独立玩家测试。

## 调整依据与规则

三名已结案参与者第一次报告需要补附件；把这种修正与错误指控同等处罚，容易让已理解案件的玩家失去探索余量。完整调查包含八次基础检查、六段证词和一次专属核验，共15 AP；它不是通关必需的最短路线。原危机每4–6回合出现，保全3 AP、甩脱2 AP，完整取证时可能超出剩余5 AP预算。

保留20 AP开局与完整证据链要求，调整如下：

| 项目 | 原规则 | 新开新版案件 |
| --- | --- | --- |
| 危机间隔 | 4–6回合 | 6–8回合 |
| 紧急证据保全 | 3 AP | 2 AP |
| 甩脱追踪 | 2 AP | 1 AP |
| 四结论正确、仅附件不足 | 每次按原动态报告罚则 | 本案首次免费补正；以后最多1 AP、信誉−8、混乱+4% |
| 任一结论错误 | 原动态报告罚则 | 保留；两种错误指控仍各有一次额外后果 |

报告与补正不推进回合。AP为0时可以提交正确报告；后续附件不足的AP损失为0，信誉和混乱处罚仍保留。免费补正不免除错误结论的处罚，也不会因刷新、重试、换设备或再次获取选项而重置。免费危机选项及其信誉、混乱后果保留，关键证据不会永久销毁。

C需要四项结论和四维支持链成立；B另需专属核验；A另需两种替代解释排除；S另需隐藏独立旁证。没有放宽答案或评级条件，也没有通过增加能力跳过核心取证。

## 玩家看到的改进

- 当前目标优先引导可达的基础物件，包括其他开放区域；基础检查完成后转向证词、专属核验、关系及报告。隐藏旁证保留地点和入口，但明确标为可选，C/B不要求取得。
- 核验前说明：合适的方法稳定取得证据；不匹配仍消耗已报价的AP、体力和一回合，并增加混乱，可重试。专属操作同样提前说明1 AP、一回合和失败混乱；数值来自公开`cost_rules`，当前为3%。免费复查不附带失败收费提示。
- 报告的四个证据组每次展开一组；职责、已选数量和名称始终显示。收起不丢选择，同一证据仍可用于不同维度；键盘可展开和选取。
- 报告显示剩余免费补正次数、附件不足的当次/用后费用，以及结论错误的费用和指控风险。以当前权威运行的`report_policy`为准，正常提交、AP变化及断线恢复后同步。
- 温和询问和明确追问提前说明用于了解背景与态度，并不保证推进关键证词；匹配证据的对峙继续稳定推进。

## 保存兼容

只有新创建的调查版本2运行初始化`investigation.balance_revision: 2`及补正额度。既有版本2运行没有该标记时，继续使用原危机间隔、费用和报告罚则；版本1继续冻结。已有`pending_crisis.choices[].ap_cost`和`next_crisis_turn`保持原值，不在恢复时重报价或重排。无需D1迁移。

`report_options`以及每次公开运行都提供当前政策；缓存的旧操作结果不能覆盖最新运行中的政策。权威操作ID、revision、会话锁、事务和一次结算继续使用原机制；补正计数保存在`run_json`中。公开政策仅含成本和额度，不增加正确方法、报告支持映射或私有答案。

## 预算与兼容验收

[16组最坏费用预算记录](v2-difficulty-budget.json)覆盖八案×默认/零能力队伍：

`8次基础检查 + 6段证词 + 1次专属核验 + 1次错误检查 + 2次保全×2 AP = 20 AP`

每组都在16回合、0 AP时完成一次免费附件补正，再提交完整报告取得B。危机测试在第6/12回合注入真实保全事件，避免依赖有利随机数；另有独立测试检查实际6–8回合调度。这证明上述有限容错预算可行，不代表不限次数试错或真实玩家完成率。更高评价仍要求玩家安排可选内容与资源。

权威回归覆盖新旧规则、已保存3 AP报价、所有四种错误结论不能免费、两类错误指控仅额外处罚一次、补正后继续收费、0 AP提交、序列化恢复、SQLite操作重放、双标签旧revision冲突与一次性结算。客户端回归覆盖政策同步、两种语言、旧界面和折叠选择保留。另验证专属核验报价与实际执行者、1 AP及10%体力扣费一致，体力不足仍可免费查看材料，完成复查费用为0。

最终完整测试852/852通过，0失败或跳过；类型检查、Lint、安全检查（407份源文件及Git历史）、资产校验、生产构建与Worker dry-run均通过。构建扫描698条私有文本、20份JavaScript、26,739个解码字面量，泄露命中及服务端导入违规为0。Worker为759.69 KiB/gzip213.03 KiB，46份静态资源。Three相关chunk仍有超过500kB的构建提示。

[原16组通关基线](v2-playthroughs.json)、[原质量门槛](v2-quality-checks.json)保留为本轮调难前记录；它们的源码哈希及计数只描述当时版本。本轮最终结果见[v2-difficulty-checks.json](v2-difficulty-checks.json)。
