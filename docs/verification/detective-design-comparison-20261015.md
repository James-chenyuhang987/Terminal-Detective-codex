# 当前版本侦探体验对照审查

日期：2026-10-15。审查对象为本地工作区，包含尚未提交的调查档案、原始材料工作台与近期修复；不代表线上版本。

本轮重新阅读八案内容、服务端判定、探员成长与3D表现代码，并由三个独立审查分工复核叙事、玩法与整体体验。参考作品机制以开发者、发行商或发行商维护的商店页面为依据。这是设计审查，没有新增真人研究、八案界面通关或手机性能测量，也没有修改游戏规则、发布或部署。

## 结论与定位

当前已经具有完整调查闭环：免费观察、探员核验、原始材料、分阶段证词、三类关系、四维报告、可修正结案和额外评级。最新档案、草稿恢复、渐进引导、脚步与角色动作均属于已有能力，不能继续把它们列成缺失功能。

与成熟作品的主要距离集中在四处：证据是否充分约束真相、八案能否带来不同的认知转折、人物是否因调查发生可信变化、探员成长是否确实改变调查体验。

保留用户认可的定位：玩家决定调查问题、假说和行动方向；系统承担专业测量、证据匹配、部分事实推断与最终裁定。辅助判断本身不是短板，辅助结果必须可解释、可信、有后续意义。

## 重要发现

### 1. 首案的最低结案证据需要补足操作者归属

`src/game/caseData.js:71–78` 的收据说明有人购买电容，维修记录说明有人使用通路；新版 `server/investigationV2/content.js:67` 又明确强调复制卡名称不能证明持卡人身份。但报告机会维度只需复制卡与维修记录，结论直接认定 Mei 实施袭击（同文件101–106行）。`rules.js:575–580` 的 C/B 不要求证词或隐藏旁证。

因此，“另一个能取得复制卡和EMP的人使用同一路径，Mei只有动机”仍是普通已知材料未充分排除的解释。这不是说另有真凶，而是当前材料对身份的约束弱于系统结论。较明确的设备—个人联系在可选隐藏旁证中（`content.js:110`）。

建议把一条可核验的“人—设备—本次操作”联系放入普通主线或必要澄清；隐藏线索继续用于独立增强，不成为主线门槛。验收时给出一个竞争解释，能用玩家实际取得的材料指出它在哪一步不成立。系统结案同时展示这一判断依据。

### 2. 八案的题材差异大于结构差异

七起死亡案的核心责任人都处在各案 `npc_01` 槽位。内部ID不会直接呈现，公开报告选项也已排序，不能称为“点第一项漏洞”；真正的风险是人设功能重复。第四至第八案尤其常见“主管掌握权限与利益—其余人物由独立记录澄清—日志重建远程操作”的结构。

应改变信息分配、可信度和转折方式：允许有权限者先被洗清一段嫌疑，再由新的动作链归责；让说谎者隐瞒与杀人无关的事情；让早期合理判断在新事实出现后需要重写。保留既有真相也能做到，不靠随机换凶手维持悬念。

### 3. 基础核验容易成为熟练后的固定点选

`content.js:8–27` 中，64个基础对象共用四类方法，正确方法都随类别默认映射：文档核对签章、终端查原始审计、样本做标准对照、设备查独立诊断。熟悉后，玩家可能不必理解当前疑点就能选对。

系统可以继续完成检测，但玩家应选择此时要验证的问题。例如同一读卡器可以检查身份来源、硬件复制或时钟误差，不同操作提供不同有效信息；只有与当前假说相关的结果才能解决疑点。失败反馈说明方法的证明范围，减少统一“方法不匹配”的反馈。

### 4. 专属工具有进步，部分关键结论出现得太早

工作台已有校时、路线、脚本、监控、材料谱、声纹与签章表现，但正式裁定主要仍是三类固定ID排序/选择（`rules.js:509–526`）。观察辅助的拖动与对齐不直接纳入裁定，这可以接受，但之后必须有值得解释的问题。

例如深潮的证据正文已经说明旧演练录音与47秒重复，工作台随后再要求选出证明重复的材料（`content.js:440`、`rawMaterials.js`）。可保留系统识别重复，把玩家任务推进到“这段播放遮蔽了什么真实动作、哪条时钟还能信、哪个授权连接到本次执行”。避免已经给答案后再做确认练习。

### 5. 审讯的三种策略还没有同等清晰的价值

`rules.js:394–448` 里只有具备指定证据的 evidence 选项推进关键证词。温和和明确追问仍花AP，主要改变措辞与态度；明确追问额外降低合作度和增加混乱。推进本身不依赖合作度。玩家会倾向只等“出示对应证据”可用。

保留自动匹配证据，让玩家选具体问题或需要解释的矛盾句：温和询问获得可核验的背景或承诺，追问固定一项说法，证据对峙触发转折。无需把六段对话全部设为必做，但每个主案应有一次人物回应真正改变理解的场面。普通人物了解可考虑免费或明确的有限收益。

### 6. 报告既有全选捷径，也有支持路线过窄的问题

`rules.js:569–573` 只检查每组是否包含所需ID，所以把所有已得证据附到四组也能满足支持条件。另一方面，额外支持组合主要仅在首案，其他案件的有效证明路线比较单一（`rawMaterials.js` 的 `REPORT_SUPPORT_ALTERNATIVES`）。

改进应聚焦论证：系统整理附件并解释“这份材料证明什么”，玩家确认关键链；接受多条事实成立的组合，指出未解释的矛盾。不要因为玩家附多而额外处罚，不硬限制附件数量，也不把合理解释变成猜作者指定组合。

### 7. 人物与结案有文本，缺少调查后的变化

`narrativeEngine.js:838–841` 以取得55%线索进入第三幕，而非按关键假说被推翻触发。`content.js` 的错误指控会写“协作暂停”“证人停止配合”，实际 `rules.js:612–620` 主要增加信誉或混乱数值。`CaseReconstruction.jsx:15–35` 已有证据链回顾，但仍偏展开列表。

建议每案设置1–2个已确认事实触发的转折；关键对峙显示原话、证据和改口原因，并有停顿、视线、姿态或声音反馈。结案自动按已确认材料讲清准备、执行、掩盖、发现，再给短人物后日谈。只呈现本局有依据的事实，未知仍标为未知。错误指控后的反应允许修复，也不封死关键材料。

### 8. 探员大厅的成长与新版调查脱节

`SkillTreePanel.jsx:36–50` 明确只有首次核验免AP、崩溃恢复免罚两类技能用于手动调查，其余大部分为旧版效果，另有三类明确目前不提供描述加成。`skillNodeState:24` 却仍要求装备前面的技能链。这会使玩家投入与实际玩法反馈不匹配。

新版应有独立、准确的技能作用：专业观察、记录来源辅助、有限风险预警、材料整理与对话策略收益。每个可装备节点都应有可触发且能解释的效果；避免把唯一核心证据锁在能力门槛后。旧付费运行仍按原规则处理。

探员已有不错的静态人物钩子，但缺少对共同案件的记忆。可以先给三名主探员各两段由实际调查事实触发的大厅交流，使“带队调查”成为作品辨识度。市场当前是明码签约，并非随机抽卡，不应误称抽卡机制。

### 9. 3D需要更强的空间叙事

当前复用5种房间、3种NPC基础角色，已有案件专属物件、NPC分区与近景细节。但 `InvestigationProps.jsx:37–44` 把对象统一放在展示台上，案件常像证物陈列；物件位置很少成为因果证据。

先做一案的真实现场关系：阀门处于可接触的高处、隔断改变证人视线、路线长度限制某个行动窗口。让位置本身能支持或排除一个解释，并给文字模式等价描述。后续模型精细度、镜头与关键声音围绕这些事实服务；现有脚步、材质声、环境声和谈话姿态继续保留。

### 10. 难度和重玩不能依靠增加清单与等待

八案已有20AP预算与有限容错验证，这证明可通关，不证明真人感到有趣或难度合适。签到、日常、周挑战、成就和S级提供完成目标，但固定真相重复游玩容易退化为背点击路线。体力是否打断连续查案仍需实际观察。

保留资源压力，让后期难度来自可靠来源冲突、可信替代解释和责任边界。主线按一次高质量体验设计；重玩可明确定位为审计挑战，用不同材料或限制条件验证已知真相，提供新的判断理由。先少量验证，避免大规模程序生成破坏证据公平性。

## 八案分别应强化的推理体验

下列为建议方向，不表示这些内容已经实现，也不要求改写当前谜底。

| 案件 | 目前可保留的特色 | 下一步应形成的主要判断 |
| --- | --- | --- |
| 霓虹血迹 | 独立时钟、复制权限与家属动机 | 权限相同不等于本人；补足实际操作者与本次动作的联系。 |
| 幽灵协议 | 主动失踪与机构违法的责任分离 | 提前建立相位设备的能力与限制，再排除不可能路径，区分没有离门记录与没有离开。 |
| 红蝶陷阱 | 安全脚本与功率异常 | 区分常规配置改动、保护绕过和实际致伤，人物隐瞒不必都指向谋杀。 |
| 零度回声 | 无人机维护路线 | 用空间尺度、工具痕与控制记录共同重建动作，让路线可以被检验。 |
| 天穹失联 | 监控视差、循环与独立回执 | 在两个看似可信的时间来源间做选择，并说明哪个来源失去证明力。 |
| 午夜拍卖 | 真伪标记、运输与维护 | 分开证明调包、货物流转与死亡责任，避免三件事自动归为同一人的行为。 |
| 深潮回声 | 旧求救声纹与真实执行时间 | 系统识别重用后，玩家重新判断仍能证明存活与动作时间的来源。 |
| 白塔悖论 | 人类批准、系统执行与删除记录 | 区分政策权限与具体致死指令；结案回应居民与治理后果。 |

## 建议实施顺序与验收

1. **先补推理可信度与有效成长。** 审查八案“身份—权限—动作—结果”的最低链；修正新版可装备技能的实际作用。验收每个结案身份判断有已取得的材料支撑，每个技能有可观察收益。
2. **精做两个结构不同的样板案。** 建议霓虹用于身份归属与关键对峙，幽灵用于非谋杀转折与空间/技术边界。先验证玩家会因新事实主动改变解释，再扩展到其余六案。
3. **补人物收束与共同经历。** 每案一场完整对峙、一个事实触发的转折、一段有证据依据的后日谈；结案故事之后再集中呈现成长奖励。大厅引用真实经历。
4. **按案件逐步扩充空间、声音与复玩。** 每案至少一个位置关系参与推理，关键事件产生可见反馈；挑战模式提供新的判断，而非加长同一流程。

新一轮测试应先观察不继承谜底的参与者能否说明：最初怀疑什么、哪条事实使其改变想法、为什么该证据能指向操作者、系统替其完成了什么判断。原五名agent试玩属于形成性检查，最新界面回归属于知情开发测试；两者均不能替代真人情绪、记忆与持续游玩意愿的验证。
