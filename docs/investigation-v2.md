# 八案现场调查与推理体验：调查内容版本 2

2026-10-15更新：[难度调整与当前验收](verification/investigation-difficulty.md)。新开版本2案件使用`balance_revision: 2`；既有案件的资源规则保持开案版本。下方16份通关和818项质量结果为调难前基线，当前检查见新验收记录。

## 版本与兼容边界

这是付费调查内容版本升级，**不是身份、档案权威协议的新版本**。接口仍返回 `authority_version: 1`；档案的 `supported_investigation_versions: [1, 2]` 表示可创建哪些调查。新版客户端确认支持 2 后，在 `start_case` 中提交 `investigation_version: 2`。省略该字段仍按版本 1 创建，不会隐式升级正在调查的案件。

已存在且没有版本字段的运行继续使用版本 1。旧问答、随机取证、连线、报告验证和结算重判均按旧版本分派；已付费案件的保存状态不改写为新版。版本 2 状态存放在现有 `player_runs.run_json` 中，本轮无需新增 D1 表结构迁移。身份、操作 ID、revision、设备会话、CAS、幂等账本和一次性结算沿用 [服务端权威协议](backend-authority.md)。

一个账号仍最多有一个未结算案件。打开卷宗浏览或选择另一案不会自动放弃旧案或重复扣费；明确换案需要先确认旧案的 `abandon`，再确认档案 `settle_case`，释放运行名额后开始目标案件。“继续调查”恢复当前案。

## 玩家操作与实际规则

版本 2 的基础循环为：**免费观察 → 指定对象、方式与探员核验 → 证据对峙 → 关系推理 → 专属操作 → 为报告四个环节附证据**。3D 和文字模式共享服务器进度。

1. 3D 视口内使用 WASD 或方向键移动，按住 R 疾跑，靠近对象或人物按 E 交互。行走 `1.4 m/s`，疾跑 `2.4 m/s`；松开移动键停止位移。触屏可使用方向按钮。也可在“现场调查台”直接选择当前区域的物件。
2. 观察说明、物件放大旋转及浏览现有记录免费。开放通道的相邻区域往返由服务端确认，但不扣 AP、不恢复探员体力、不推进回合，也不能靠往返刷出隐藏线索。
3. 确认核验前选择执行探员和方法，查看 AP、体力及风险。基础核验消耗 1 AP、推进 1 回合，执行探员消耗 10 体力，并沿用每回合恢复规则。正确方法稳定获取对应证据，能力为零也不会因概率失去唯一主线。
4. 选错核验方法仍付成本、推进一回合，混乱增加3%，但物件保留并可重试。已核验对象只提供免费复查，不重复付费、不重复产证。每案三个对象分别有观察、逻辑或系统审计的专业补充；对应执行探员基础能力达到60且正确核验后，才返回该补充，并随已完成记录保存供免费复查。它只解释当前已核验结果，不增加其他证据、报告依赖或费用。扫描技能将首个核验的 AP 成本减免一次，不会直接自动发放线索；高专长探员的首次减免也有每案一次的上限，具体成本以服务端报价为准。
5. NPC 只出现在案件配置的所在区域。温和询问、明确追问与证据对峙产生不同反应；取得对应材料后的证据对峙稳定推进两段专属事实。无辜角色提供澄清，不因压力统一“认罪”。问答报价及可用性以当前回合、体力和记录为准。
6. 证据连线选择“支持”“矛盾”“先后关系”，成功形成可读命题。“先后”有方向；相同证据对可以在不同关系下形成不同命题。首案复制卡读卡23:16可先于维修井启用23:17，二案屋顶压力02:34可先于设备回收02:41；不能把回收当使用、重叠时间窗当严格先后，或仅凭两次人类权限操作猜测先后。错误关系给关系类型、原始时钟与方向的中性引导，仅对同一次尝试增加一次混乱，之后可改选；重复命题不重复获得推理碎片。75条命题中，每案用于A评级的替代解释排除仍各两条，额外时间命题不代替它们。每案已取得的隐藏独立旁证也各有一条对应事实的支持命题，例如深潮黑匣子支持远程开阀；隐藏物件可观察但尚未核验时不能连线，独立支持不会代替替代解释排除或额外提高评级。
7. 完成专属操作需要先取得公开的相关材料。时间排序与路线重建需要排列全部节点；并列比对需要选择吻合项。按钮支持键盘和触屏，未正确完成可复查重试，正确结果仍由服务端判定；已完成操作免费回看。
8. 当前目标优先可达的基础对象，随可调查对象和已确认事实变化，并指出目标对象所在区域。隐藏旁证明确为可选。隐藏对象仅在前置与回合条件成立后，公开名称和所在区；公开目标的`zone_label`与`current_goal_target`支持区域引导。提示分为方向、核验建议和已知事实，后两项按需展开；它们不公布正确方法、未来证词或隐藏答案。危机仍影响资源与信誉，但不会永久销毁版本 2 的关键原件。

证据危机选择延期会保留原件，服务器明确返回截止回合；继续推进超过截止回合后，信誉减少5、混乱增加5。免费复查不推进回合，也不会取消这次延期后果，不能把“保留原件”理解为已经解除危机。

### 报告与结案

报告选择核心结论、手段、动机、时间线，并分别给 `opportunity`、`method`、`motive`、`timeline` 附上已获取证据。**每个维度必须覆盖该环节的完整支持链，只有一条暗示性证据不够。** 同义正确责任归因使用规范选项；客户端不能自报分数。

| 评级 | 条件 |
| --- | --- |
| D | 结论错误或任一环节证据不足；反馈已知事实中的缺口，允许继续调查和修改。 |
| C | 四项结论正确且完整证据链覆盖四个环节。 |
| B | 满足 C，另完成本案专属核验。 |
| A | 满足 B，另确认两条排除主要替代解释的命题。 |
| S | 满足 A，另取得条件隐藏物件的独立旁证。 |

新开案件中，四项结论正确、仅附件不足时本案首次免费补正；此后最多扣1 AP、信誉−8、混乱+4%。错误结论仍按原动态罚则，每案两种错误指控另有不同的一次性信誉或混乱后果。额度保存在权威运行中，旧案保持原规则。证据不足时，反馈解释缺失维度应证明的职责：机会需要实际在场或控制，手段连接异常与伤害，动机证明具体利害，时间线区分准备、执行、发现与事后活动。只给通用方法，不列未发现的正确证据或答案；报告错误不会把案件立即变成已结案。

**第一次通过的报告会结束该运行。** 如果希望 A 或 S，应在提交前完成对应调查；已经以 B 结案后不能在同一运行继续调查升级。自动测试的 B/A/S 对比是从同一报告前进度建立独立分支，分别验证评级，不是同一付费案件反复领取奖励。最终奖励仍需 `settle_case`，服务端重判保存报告并只结算一次。

## 八案内容与修正

每案有 8 个具名基础调查对象、1 个条件隐藏对象、3 名合理分区 NPC 各两次证词进展，以及两种不同错误归因后果。对象观察、结果、初始证词、后续证词、推理命题、报告候选与操作材料均提供中英内容。报告候选以相近篇幅表述可比较假说，避免靠“最长就是正确”或措辞暗示猜答案。

| 案件 | 专属核验 | 主线调查差异 | 隐藏最早回合 |
| --- | --- | --- | --- |
| Lvl_01 霓虹血迹 | 门禁与致伤时间轴排序 | 分离复制权限、致伤与发现时间 | 8 |
| Lvl_02 幽灵协议 | 密室逃出路线重建 | 分离人员离开机制与机构密钥交易 | 7 |
| Lvl_03 红蝶陷阱 | 安全锁脚本差异比对 | 识别软件绕过、安全限额与后台窗口 | 6 |
| Lvl_04 零度回声 | D-4维护路线重建 | 用履带、扭矩和喷射方向追溯远程路径 | 7 |
| Lvl_05 天穹失联 | 监控视差与事件排序 | 用独立回执校正循环画面 | 8 |

隐藏线索还需要指定前置核验及独立对象检查，达到回合数不会自动获得。它们只用于提高评级，C/B主线不依赖隐藏奖励。

## 协议与模块

`playerProfile` 和 `playerRun` 保留现有请求信封：会话 ID、操作 ID、预期 revision；`playerRun` 还需 `run_id`。仅提交玩家意图，服务端验证对象所在区域、入口条件、已持证据、体力与报价版本。语法非法拒绝；合法业务拒绝保存错误结果及一次 revision 更新，重放不再执行扣费。

创建版本 2 案例：

```json
{
  "action": "command",
  "session_id": "current-device-session",
  "operation_id": "new-unique-start-operation",
  "expected_revision": 12,
  "command": {
    "type": "start_case",
    "case_id": "Lvl_01",
    "investigation_version": 2
  }
}
```

以下均为 `playerRun.command`，可附 `lang: "zh" | "en"`：

| 命令 | 意图字段 | 行为 |
| --- | --- | --- |
| `inspect_options` | `target_id` | 返回当前对象各探员的核验报价包；只包含公开方法与成本，不标正确方法。 |
| `inspect` | `option_id` | 使用服务器刚签发的对象/方法/执行者/revision绑定报价；返回结果及权威进度。 |
| `travel` | `zone_id` | 只允许相邻、满足入口条件的区域；已访问区域免费往返。 |
| `interrogation_options` | `npc_id` | 现有提问接口，版本 2 从该 NPC 当前证词阶段签发问题。 |
| `question` | `npc_id`, `question_id`, 可选 `executor_agent_id` | 选当前报价问题；证据对峙推进相应阶段。 |
| `link` | 两个不同 `clue_ids`, `relation_type` | 关系值为 `supports`、`contradicts`、`precedes`；时间先后按数组方向。 |
| `puzzle_options` | 无 | 达到材料条件后返回公开操作节点；不返回答案。 |
| `puzzle` | `answer_ids` | 当前节点 ID 的排序/匹配选择，由服务端判定。 |
| `report_options` | 无 | 返回四组规范候选及已获得可附证据。 |
| `report` | 四个结论 ID, `evidence_by_dimension`，可选 `evidence_ids` | 四维证据分组必需；各组0–9个不同已持ID，空组或缺链不会通过。 |

版本 2 禁止 `decision_options` / `round` 自动随机搜证，返回 `MANUAL_INSPECTION_REQUIRED`。`rest`、危机、优先级、紧急稳态、崩溃恢复与放弃继续通过权威运行接口执行。版本 1 的自动调查按公开风险和优先级选择，而非把洗牌后的首张卡当作“稳健路径”。

关键模块：

- `server/investigationV2/content.js`：仅服务端的八案完整内容、正确方法、证词推进条件、报告支持链与独立隐藏奖励；`getInvestigationContent(caseId)`、`INVESTIGATION_CASE_IDS`，返回内容不可原地修改。
- `server/investigationV2/rules.js`：核验、入口、专属问答、关系、操作及报告判定；初始化修正文案和对象区域，公开投影仅返回观察材料、已确认结果和当前可用入口。
- `server/gameAuthority/runAuthority.js` 与档案/Worker入口：创建和命令验证按保存的内容版本分派，结算也按该版本重判，不接受客户端总结。
- `scripts/browser-case-projection.mjs` 与 `vite.config.js`：只投影Vite浏览器目录，词条`keyword`统一为“待核验证据”/“Unverified evidence”，`weight`统一为`MEDIUM`；移除旧版未发现证据描述和正确关系解释，包括开发源码映射与`?raw`导入。Node/Worker原始目录及版本1裁定保持不变，真实词条、描述和权重只随已经取得的权威`revealed_clues`接收。
- `src/components/game/investigation/`：现场调查台、物件查看器、版本2报告交互；`src/game/investigationChoices.js` 提供客户端公开报价选择。
- `src/game/theaterWorld.js` 与 `src/components/game/theater/`：对象位置、人物分区、通道与现场交互；Blender物件生成器保存新临时 `.blend`，不覆盖原人物源文件。
- `src/game/theaterAudio.js`、`theaterQuality.js`：依据落脚相位、材质和房间的声音反馈，以及带冷却的持续帧耗时画质调整。界面截图及性能测量由独立验收报告提供。

旧的无状态`detectiveRules`公开端点已退役：已登录POST固定返回410 `STATELESS_RULES_RETIRED`，不解析或裁定上传的伪造案件；未登录为401，非POST为405。两个版本都通过`playerRun`继续现有权威运行，旧案裁定和结算保持冻结。真实JWT/SQLite回归覆盖24种探测，确认运行与操作账本不变。

正确方法、未来回答、私有支持映射、谜题答案和未满足条件的隐藏奖励不会写入公开投影或浏览器产物。查看页面中的对象候选不能绕过服务端裁定。断线重试沿用原操作 ID 和意图；采用当前服务器运行后重新取报价，不能复用已经过期的 `option_id`。

### 已结案档案的只读恢复

档案响应的顶层`archive_clue_labels`仅为各条`case_records.discovered_clues`中的已取得ID提供中英名称，来源为服务端原始目录，不传未发现名称、证据描述、证词或正确关系。关系图使用该投影显示已发现材料；没有可用名称时显示“已发现证据”，未发现节点仍显示“未知证据”。

`ProfileContext`按服务器档案中的ID再过滤一次，保存为独立的只读`archiveClueLabels`；它不写入`profileRef`、本地操作回执或待重试指令。刷新档案重新取该显示投影，退出或换账号后清除，因此旧档案可以恢复可读关系图，而不重写旧付费运行、证据ID、档案revision或结算规则。

[16份完整记录](verification/v2-playthroughs.json)直接从 `/tmp/td-v2-authority-tests.log` 的测试 diagnostic 解析，保留来源 SHA-256；对应 `node --test tests/investigationV2Authority.test.js` 的47/47通过结果，内容专项为61/61。没有使用生产账号、云端奖励或人工试玩结果代替测试。

存储bytes为测试中最终S分支整个私有运行JSON的UTF-8序列化大小，不是网络响应大小、GPU性能或试玩时长。范围21,317–22,889 bytes，低于当前512 KiB运行上限；最长历史仍受该上限保护，不能据此承诺无限记录。
